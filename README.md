# ZalogHub — ToDo

Канбан-доска задач с тремя колонками: **Бэклог → В работе → Выполнено**.
Данные хранятся в `localStorage` и сохраняются после перезагрузки страницы.

## Возможности

- **Создание задачи** — кнопка «+» в колонке «Бэклог» открывает модальное окно. Пустую задачу или задачу из одних пробелов создать нельзя.
- **Перетаскивание (drag-and-drop)** — между колонками и внутри колонки. Задачу можно вставить в любое место чужой колонки.
- **Правила переходов** — задачу можно перенести только в соседнюю колонку. Перенос «через колонку» (например, из «Бэклога» сразу в «Выполнено») запрещён.
- **Переименование** — по кнопке-карандашу или двойному клику по названию. Enter или клик мимо сохраняет, Escape отменяет.
- **Удаление** — с подтверждением в диалоговом окне.
- **Фильтр** — поиск по названию и выбор статуса: все, бэклог, в работе, выполнено. Колонки видны всегда, фильтр скрывает только карточки.
- Выполненные задачи зачёркнуты и приглушены.
- Кнопки действий появляются при наведении на карточку. На тач-устройствах они видны всегда.

## Архитектура

```
src/
├── types/                 типы домена
│   ├── todo.ts            Todo, TodoStatus, TODO_STATUS, TodoPlacement, TodoColumns
│   └── todo-filter.ts     TodoFilter, StatusFilter, STATUS_FILTER
├── features/todos/
│   ├── model/             бизнес-логика: чистые функции без React и Zustand
│   │   ├── todo.ts        создание, валидация, переименование, смена статуса
│   │   ├── status.ts      порядок колонок и таблица переходов
│   │   ├── placement.ts   положение задачи на доске
│   │   └── filter.ts      фильтрация и раскладка задач по колонкам
│   └── ui/                React-компоненты и хук перетаскивания
├── store/
│   └── todo-store.ts      Zustand-стор: состояние и действия поверх модели
└── components/ui/         примитивы shadcn/ui
```

Зависимости направлены в одну сторону, циклов нет:

```
types  ←  model  ←  store  ←  ui
```

- **`model/`** не импортирует `react`, `zustand` и `@/store`. Бизнес-правила живут только здесь.
- **`store/`** хранит состояние и вызывает функции модели. Собственной логики в нём нет.
- **`ui/`** отображает данные и вызывает действия стора.

### Бизнес-правила

| Правило                                             | Где                              |
| --------------------------------------------------- | -------------------------------- |
| Название обрезается по краям, пустое не принимается | `normalizeTitle`, `isValidTitle` |
| Новая задача попадает в бэклог                      | `NEW_TODO_STATUS`, `createTodo`  |
| Переход возможен только в соседнюю колонку          | `STATUS_TRANSITIONS`, `canMove`  |
| Любое перемещение проверяет переход                 | `moveTodo` → `placeTodo`         |
| Фильтр по названию и статусу                        | `matchesFilter`, `boardColumns`  |

### Ключевые решения

**Статусы и переходы.** Порядок колонок задан в `TODO_STATUSES`, допустимые переходы — в таблице `STATUS_TRANSITIONS`. Тип `Record<TodoStatus, …>` не даст забыть переходы для нового статуса: TypeScript потребует строку в таблице.

**Порядок задач — это порядок массива `todos`.** Отдельного поля для позиции нет. Позиция задаётся через `TodoPlacement`, «поставить перед такой-то задачей»:

```ts
interface TodoPlacement {
  status: TodoStatus
  beforeId: TodoId | null // null — в конец колонки
}
```

Позиция указывается относительно соседней задачи, а не по номеру. Поэтому перестановка работает правильно и при включённом фильтре: скрытые задачи не сбивают порядок.

**Одна функция для превью и результата.** Во время перетаскивания доска рисует черновик `placeTodo(снимок, id, позиция)`. После броска в стор записывается `placeTodo` с той же позицией, поэтому результат совпадает с превью. Над запрещённой колонкой `placeTodo` отклоняет переход и возвращает снимок, и исходная колонка сразу показывает первоначальный порядок.

**Встроенная оптимистичная сортировка dnd-kit отключена** (`preventDefault` в `onDragOver`). Во время перетаскивания DOM меняет только React. Иначе при переносе между колонками React падает: dnd-kit уже переместил узел, а React пытается удалить его со старого места.

**Фильтр не сохраняется.** В `localStorage` попадают только задачи (`partialize`). Фильтр — состояние текущей сессии.

## Хранение данных

Ключ `localStorage`: `zaloghub-todos`.

```json
{
  "state": {
    "todos": [{ "id": "…", "title": "Купить молоко", "status": "BACKLOG" }]
  },
  "version": 1
}
```

При несовместимом изменении формата нужно поднять `version` в `todo-store.ts` и добавить `migrate`.
